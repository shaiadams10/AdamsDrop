# Operation and recovery

Windows -> iPad is automatic. iPad -> Windows requires SendToWindows. Offline copies are not history to reconcile: copy again when connected. Superseded Windows copies and old incoming SSE events are rejected. Receipts are coalesced; stale queued receipts expire. Already queued APNs/ntfy notifications can still arrive, and manual/large-image fallback is transient rather than guaranteed live delivery.

Startup: manual executable launch (or optional login-only task) -> Apple connection helper -> developer tunnel warmup. Next copy retries if unavailable. Missing iPad developer support is remounted after reboot; a timed-out clipboard helper can be restarted at most once per minute. Only the exact developer helper is targeted, not Notes or the system clipboard daemon.

Troubleshooting: check AdamsDrop.exe; unlock iPad on same LAN; copy fresh short text; allow cold-start recovery; inspect metadata-only listener.log beside executable. If still unavailable, connect USB, open Apple Devices and run the mount command in IPAD.md, then relaunch AdamsDrop.

Logs and saved incoming video/image files are private. Direct clipboard contents are not logged. The imported-origin clipboard marker prevents echoes and is replaced by a fresh local copy.

iPad original-video sharing uses the same SendToWindows shortcut and relay endpoint. Raw video uploads stream through temporary relay disk storage (2 GiB per file, 4 GiB total); Windows saves original bytes in Downloads/AdamsDrop after length and SHA-256 verification. A video automatically reveals its containing folder in File Explorer with the exact saved file selected when full-screen protection is off. An enabled notification can reveal it again on click. There is no deferred opening after protected activity. The video path never touches the clipboard. Share Media/Files as a raw File body, with Photos sharing format Current; see IPAD.md. Send again after interruption or full-screen protection. Pending relay videos expire after ten minutes; downloaded Windows files remain until deleted. A relay restart discards pending transfers and clears spool leftovers. This is transfer storage, not backup.

Incoming screenshots/images copy to the clipboard and save separate original files in the receive folder. Their notifications reveal the saved image in Explorer only when clicked, with no automatic folder opening. Images are no longer overwritten in a single last_clip.png cache file. If saving an image file fails, the successful clipboard copy is preserved and its notification has no file action. Saved images remain until deleted; old cache files are retained with prior builds for rollback.

Generic iPad files (PDF, CSV, JSON and other formats) use the same Shortcut and shared bounded relay spool. `windows-client/file_transfer.py` handles original bytes, length/SHA-256 verification and unique file naming; video_transfer.py adds video-specific validation. Generic files save in Downloads/AdamsDrop or receive_file_dir, leave the clipboard unchanged and reveal only when their notification is clicked. Empty files and named text files are supported. The optional filename header preserves extensions when Shortcuts uses generic MIME; unnamed ordinary text remains clipboard text. File/video limits share the existing server settings. Physical iPad export remains an owner acceptance step.

Owner confirmed operation after Windows reboot. Actual iPad reboot preserved trust but removed developer support; Wi-Fi remount and subsequent text/image transfers passed. Integrated automatic remount is implemented, not certified for every reboot/OS/lock combination. No always-delivered guarantee. Experimental native reverse readers were removed from shipped software.

Packaging validation: renamed executable passed direct text and image read-back while the iPad was awake (about 177 / 203 ms in one sample). After the final icon rebuild, relay-to-Windows text/image and origin markers passed again. A later direct check found the iPad undiscoverable, so always-available or final-build reboot delivery is not claimed. The relay healthcheck is healthy.

Windows quiet-operation update: no repeating recovery trigger or failure restart; closing the tray exits. Manual launch does not depend on Task Scheduler. Below-normal process priority, nonblocking send admission, bounded rotating logs, quiet receive defaults, and tray-failure exit reduce background impact. Overlapping copies are dropped; copy again when ready.

Full-screen protection skips new transfer work while Windows reports busy/exclusive-game/presentation state or the foreground borderless window covers its monitor. No backlog is replayed afterwards. Incoming PNG encoding occurs before the Windows clipboard is opened. Login-only startup waits 30 seconds; there is no repeating trigger or restart-on-failure. See WINDOWS.md for detection and in-flight-work limitations.


Windows original files now use explicit `--send-files` / tray Send Files to iPad / Explorer Send to. `send_files_to_ipad.py` streams original bytes through the existing relay with filename/length/SHA-256; Windows file mode is opt-in and selects the new SaveToFiles shortcut. iPad file downloads use binary attachments to prevent Shortcuts JSON/text decoding. No new server, dependency, polling or scheduling is needed; the sender is a one-shot process. Each file has its own ten-minute single-use notification. HTTP 200 means queued, not saved. See IPAD.md for the download, local save and Quick Look setup; a physical image save and persistent preview passed owner acceptance.


For immediate file use on iPad, SaveToFiles should finish with **Quick Look → Saved File**, directly after Save File. The save location is whichever folder is selected inside Save File; it is not determined by the relay. Delivery scope is Windows plus the relay host only; any Mac connection is outside this project. The notification flow remains the owner's preference.


Stream Deck: `AdamsDropSend.exe` (a sender entry point sharing the installed runtime) sends selected foreground Explorer files or opens the native picker. `send_files_to_ipad.py` reads selection through Shell COM without clipboard writes, and `transfer_progress.py` renders native preparation/upload/notification-submission status only during explicit sends. The sender exits after the panel closes, with no background watcher, polling or scheduler. Notification submission is confirmed; banner delivery and iPad persistence are not. The old Explorer Send to and tray paths use the same panel. Build tooling copies the companion entry point; stop.ps1 stops both installed executable paths for upgrades.

Windows 11 tab selection fix (October 12): Explorer exposes several COM entries sharing one frame HWND. The sender now matches each Shell browser's IOleWindow to the active ShellTabWindowClass child, instead of rejecting every multi-tab frame. It verifies focus/tab stability before returning, retains the single-entry legacy path, and falls back to the picker if identification fails. All COM objects are released before apartment teardown. No focus changes, clipboard access, new dependencies or background monitoring are needed. File sending already accepts every extension through explicit kind=file; coverage now includes videos, text/JSON/CSV, archives, unknown and empty files with byte preservation.

Packaged acceptance passed: a no-argument companion launch sent the real selected synthetic PDF from a multi-tab Explorer window without opening the picker. Packaged PDF/PNG/JSON/TXT/CSV/MP4/MOV/ZIP/unknown-extension/empty-file sends through real local HTTP preserved exact bytes, checksums and filenames, with ntfy mocked. These tests leave physical iPad preview/codec acceptance separate. Full-screen protection remained enabled throughout successful acceptance. CI also runs the synthetic relay file/video and Windows sender/receiver/protection checks.

Notification timing: after successful publication the native card holds a blue **Notification on its way / Upload complete / 100%** state for three seconds, then a green confirmation for 1.8 seconds. Event-driven native one-shot timers provide this display grace without delaying the actual send or adding polling. This is an estimate, not a delivery receipt. IPAD.md describes optional Go to Home Screen/Open App actions after Quick Look; automatic return to an unknown previously active app is unavailable in the current notification flow.
